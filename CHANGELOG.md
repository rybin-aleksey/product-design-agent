# Changelog

Версии шаблона агента. Продукт обновляется до нужного тега: `git merge vX.Y.Z` (подробно — в [UPDATING.md](UPDATING.md)).

Формат версии: `MAJOR.MINOR.PATCH`
- **MAJOR** — меняется структура папок или контракты скиллов; в продукте нужны ручные действия.
- **MINOR** — новый скилл, workflow или знание; продукт обновляется без действий.
- **PATCH** — исправления текста и мелкие правки.

В каждой записи раздел «Что сделать в продукте» — если после обновления нужны ручные шаги.

## [Unreleased]

- Скилл `design-system-grow` — расширение UI-кита существующей ДС (grow_ui_kit): новые компоненты в секции «UI Kit — extended» с привязкой к тем же Variables и TextStyles, запись в `components.md` и аудит консистентности.
- Скилл `design-system-variants` — расширение матрицы вариантов, состояний и размеров у существующего компонента (component_variants), режимы single и bulk.
- Скилл `final-screens` — сборка финальных экранов из wireframe и UI-кита (final_screens): анализ достаточности wireframe, вынос повторяющихся блоков в UI-кит, composition map, инстансы с привязками к ДС, edge cases; режимы single и bulk.
- Скилл `screens-audit` — аудит собранных экранов на консистентность с ДС (screens_audit): шесть проверок, read-only по умолчанию, автофиксы в `--fix` с апрувом на каждый.
- Скилл `storybook-catalog` — каталог компонентов в Storybook на React-базе (storybook): Foundation, stories CSF3 + autodocs, живые переходы, песочницы.
- Скилл `react-screens` — сборка статичного экрана в React из компонентной базы по фрейму Figma (screens): отзывчивая раскладка из Auto Layout, токены, реестр экранов и навигационная страница-индекс; без логики и данных.
- Скилл `react-wire` — оживление статичных экранов (wire): навигация, единый слой мок-данных, формы с валидацией, состояния и edge cases, опционально анимации; без бэкенда, деплоя и метрик.
- Скилл `github-handoff` — передача проекта разработке через GitHub (handoff): один коммит и один пуш, README для разработчика, запись в `project.md`.
- Скилл `deploy` — публикация прототипа (deploy): сервис (Vercel / Netlify / Cloudflare Pages) или свой VPS по IP, обязательный SPA-fallback, доступы транзиентно, ссылка в `project.md`.
- Скилл `ut-dashboard` — дашборд юзер-тестов (dashboard): сбор событий на своём VPS (служба), https-туннель ngrok для прототипа на Vercel, трекер в прототипе, сценарии и гипотезы с порогами из материалов проекта, план теста в `artifacts/validate/`.
- Workflow `design-task`: ветки «Расширение UI-кита», «Расширение вариантов и состояний», «Сборка финальных экранов», «Аудит экранов», «Каталог компонентов в Storybook», «Сборка экранов в коде», «Оживление экранов», «Передача разработке», «Публикация прототипа» и «Юзер-тесты на прототипе».

## v1.0.0

Первая версия шаблона: один продукт, много задач.

- Структура `workspace/product/` с контекстом, задачами и общей папкой дизайн-системы `ds/`.
- Скилл `design-system-from-0` — стартовая дизайн-система с нуля.
- Скилл `design-system-scan` — индексирование существующей дизайн-системы из Figma.
- Workflow `design-task` с ветками создания и подключения дизайн-системы.
- Контракт дизайн-системы подхватывается по правилу в `AGENTS.md`; корневые `CLAUDE.md` и `AGENTS.md` скиллы не меняют.
- `UPDATING.md`, `CHANGELOG.md`, `.gitattributes` для обновления продуктов из шаблона.
