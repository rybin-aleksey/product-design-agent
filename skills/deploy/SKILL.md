# Публикация и деплой (deploy)

## Назначение

Выложить рабочий прототип в сеть и дать публичную ссылку:
выбор пути → сборка и SPA-fallback → публикация (сервис или свой сервер) → проверка внутренних роутов → запись ссылки.
Командную строку и подключение ведёт агент; пользователь проходит браузерные шаги (сервис) или даёт доступ к серверу (VPS).

## Когда использовать

- Запускается из ветки «Публикация прототипа» в [workflows/design-task](../../workflows/design-task/README.md) **только по явной команде пользователя** (`deploy`, «опубликуй», «выложи прототип»). Публикация — внешнее действие: прямой запрос обязателен по `AGENTS.md`, и он не распространяется на другие сервисы и серверы.
- Прототип работает локально (обычно после [react-wire](../react-wire/SKILL.md)), `npm run build` проходит.
- Нужна публичная ссылка — для юзер-теста, показа, передачи.
- Повторный запуск: в `workspace/product/project.md` есть раздел «Публикация» — обновляем тем же путём.

## Два пути

| | A. Сервис (по умолчанию — Vercel) | B. Свой VPS |
|---|---|---|
| Откуда | GitHub-репозиторий ([github-handoff](../github-handoff/SKILL.md)) | `dist` напрямую по SSH |
| Ссылка | Production Domain сервиса, HTTPS | `http://<IP>:<порт>`, без домена и HTTPS |
| SPA-fallback | `vercel.json` / `public/_redirects` | nginx `try_files $uri /index.html` |
| Обновление | Пуш в `main` → авто-пересборка | Пересборка и перезаливка `dist` |
| Пользователь делает | Браузерные шаги в сервисе | Даёт доступ к серверу |

## Роль

DevOps-инженер, который выкладывает фронтенд-прототипы: знает про SPA-fallback, не оставляет секретов в файлах, на чужом сервере действует аккуратно — ничего не ломает из уже работающего (VPN).

## Входные данные

- Код: `workspace/product/code/` (`package.json`, `vite.config`, роутер).
- `workspace/product/project.md` — разделы «Репозиторий разработки» (из handoff) и «Публикация» (если повторный запуск).
- Путь A: доступ к GitHub-репозиторию; аккаунт в сервисе.
- Путь B: IP сервера и способ входа (SSH-ключ предпочтительно, пароль — крайний вариант).

## Фазы

| Фаза | Что делаем | Результат | Гейт |
|---|---|---|---|
| 0. Путь и подготовка | Выбор пути; `npm run build`; `base: '/'`; `.gitignore`; SPA-fallback | Чистая сборка | Сборка без ошибок |
| A1. Репозиторий | Актуальный прототип в `main` через github-handoff | Свежий код в репозитории | Пуш прошёл |
| A2. Сервис | Конфиг fallback; браузерные шаги импорта | Деплой | Сборка на сервисе успешна |
| A3. Публичность | Убрать защиту Vercel, стабильная ссылка, проверка роутов | Публичная ссылка | Роуты без 404 в приватном окне |
| B1. Доступ | SSH-ключ / пароль транзиентно; разведка сервера | План изменений | **Подтверждение плана** |
| B2. Отдача | nginx на свободном порту, заливка `dist`, порт в firewall | Работающий сайт | `nginx -t`, VPN жив |
| B3. Проверка | `http://IP:порт`, внутренние роуты, оговорки | Публичная ссылка | Роуты без 404 |
| Финал | Раздел «Публикация» в `project.md`, итог | Ссылка записана | Без доступов в файлах |

## Жёсткие правила

1. **SPA-fallback обязателен** в обоих путях; проверяется вживую прямым переходом на внутренний экран.
2. **Доступы транзиентные.** Пароль сервера и токены — не в файлы, `.git/config`, `project.md`, не повторяются в ответах. Предпочтительно SSH-ключ, чтобы пароль вообще не проходил через чат.
3. **Только свежий билд.** Путь A — репозиторий обновлён до деплоя; путь B — `dist` собран в этом запуске.
4. **VPN не задевать.** Свободный порт; отдельный конфиг nginx, существующие не правятся; `nginx -t` перед reload; firewall не включается, если был выключен, и его политики по умолчанию не меняются.
5. **Перед изменениями на сервере — план и подтверждение** (что ставим, какой порт, какие файлы).
6. **Не заливать** `node_modules`, исходники и `.env` на сервер; в репозиторий — `node_modules`, `dist`, `.env*`.
7. **Ссылка — стабильная** (Production Domain), а не URL конкретного билда.
8. **Не делаем:** домен, HTTPS-сертификат, метрики, бэкенд — отдельные задачи.
9. **Файлы шаблона агента не меняются;** конфиги деплоя кладутся в `workspace/product/code/`.

## Где сохранять

```text
workspace/product/
├── project.md                 # раздел «Публикация»: путь, ссылка, порт / сервис, последнее обновление (без доступов)
└── code/
    ├── vercel.json            # путь A, Vercel: rewrite на /index.html
    └── public/_redirects      # путь A, Netlify / Cloudflare Pages: /* /index.html 200
```

Путь B: конфиг nginx и `dist` живут на сервере (`/etc/nginx/sites-available/<app>`, `/var/www/<app>`); копия конфига для истории — в заметке `project.md` не нужна, достаточно порта и пути.
Корневые `CLAUDE.md` и `AGENTS.md` не меняются.
