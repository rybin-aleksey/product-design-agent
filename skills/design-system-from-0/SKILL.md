# Стартовая дизайн-система с нуля (ds_baseline)

## Назначение

Поставить стартовую ДС на продукт без дизайн-системы за один прогон:
бриф → `foundation.md` → Figma Variables → секция «Foundation» с базовыми компонентами → контракт ДС.
Один прогон, один Figma-файл, один набор артефактов.

## Когда использовать

- Запускается из ветки «Создание дизайн-системы с 0» в [workflows/design-task](../../workflows/design-task/README.md).
- Пользователь просит «поставить / создать дизайн-систему с нуля», «завести токены и UI-кит».
- Нет `workspace/product/ds/CONTRACT.md`.

**Не использовать**, если у продукта уже есть ДС (существует `workspace/product/ds/CONTRACT.md`): расширение UI-кита, новые варианты и состояния, ребрендинг — отдельные задачи поверх существующей ДС. Если ДС уже собрана в Figma, но не проиндексирована, используй [design-system-scan](../design-system-scan/SKILL.md).

## Роль

Дизайн-системный архитектор: 5+ лет в продуктовом дизайне, ставил ДС с нуля, различает примитивные, смысловые и компонентные токены, пишет Variables через Figma Plugin API.

Адаптация роли под продукт (по ответам брифа):

| Продукт | Фокус |
|---|---|
| B2C веб | Конверсия и доверие, отступы под плотные карточки |
| B2B SaaS | Дашборды, плотная типографическая шкала, четыре уровня нейтралов |
| Мобильное приложение | Тач-таргеты от 44pt, мобильная типографическая шкала |
| Лендинг | Маркетинговые страницы, крупная шкала, акцент работает на CTA |

## Входные данные

- Контекст продукта из `workspace/product/context/` и папка задачи `workspace/product/tasks/<TASK-ID>/` (для рабочих заметок).
- Ответы на пять вопросов брифа (фаза 1).
- Ссылка на Figma Design-файл продукта: тот же, где лежат wireframes или будут финальные экраны (фаза 3).

## Фазы

| Фаза | Что делаем | Результат | Гейт |
|---|---|---|---|
| 1. Бриф | Пять вопросов одним блоком | `ds/brand-brief.md` | Ответы зафиксированы |
| 2. Foundation | Два слоя токенов в Markdown | `ds/foundation.md` | **Апрув пользователя** |
| 3. Figma | Мутирующие вызовы `use_figma` + проверочные чтения | Variables, секция «Foundation», 7 компонентов, `ds/components.md` | Проверка по факту пройдена |
| 4. Контракт | Правила работы с ДС | `ds/CONTRACT.md` | Без фазы 4 прогон не завершён |

Подробности каждой фазы, код и правила отрисовки — в [methodology.md](methodology.md).
Гейты и проверки — в [checklist.md](checklist.md).
Шаблоны файлов и отчётов — в [output-template.md](output-template.md).

## Жёсткие правила

1. **Никаких MCP-вызовов до апрува `foundation.md`.** Текстовые правки бесплатны, перерисовка в Figma — нет.
2. **Только `use_figma`.** Перед первым вызовом загрузи скилл `figma-use`; для Figma MCP сначала `create_session` с `fileKey`.
3. **Variables всегда, прибитые значения никогда.** Цвета, радиусы, отступы и размеры шрифта задаются только через Variables, а типографика через TextStyles.
4. **Semantic ссылается на Primitive** через `VARIABLE_ALIAS`. Прибитые значения в Semantic запрещены.
5. **Компоненты — настоящие `ComponentNode` / `ComponentSet`**, не фреймы.
6. **Auto Layout везде.**
7. **Имена точно как в `foundation.md`.** Без переименований по ходу.
8. **Один Figma-файл на продукт.** Не плодить файлы.
9. **Никакого `throw` в конце мутирующего вызова**: он откатывает всю транзакцию. Отчёт делается отдельным read-only вызовом.
10. **Без фазы 4 директива не завершена.**

## Где сохранять

```text
product-design-agent/
└── workspace/product/ds/
    ├── brand-brief.md         # пять ответов брифа
    ├── foundation.md          # два слоя токенов
    ├── components.md          # каталог 7 базовых компонентов с Node ID
    └── CONTRACT.md            # правила работы с ДС
```

Ниже `ds/` означает `workspace/product/ds/`. Все файлы дизайн-системы создаются только там, а не в папке задачи: ДС общая для всех задач продукта. Рабочие заметки прогона кладутся в `workspace/product/tasks/<TASK-ID>/analysis/`.
Корневые `CLAUDE.md` и `AGENTS.md` не меняются: это файлы шаблона агента, а контракт агент находит по правилу в `AGENTS.md`.
Перед созданием файлов проверь, что их ещё нет. Существующую ДС не перезаписывай без прямого указания.
