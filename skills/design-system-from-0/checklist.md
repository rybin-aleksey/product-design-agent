# Чек-лист: стартовая ДС с нуля

Проходи по гейтам последовательно. Непройденный пункт значит, что следующая фаза не начинается.
`ds/` означает `workspace/product/ds/`. Все файлы ДС создаются только там.

## Перед стартом

- [ ] Папка задачи определена (`workspace/product/tasks/<TASK-ID>/`) — для рабочих заметок в `analysis/`.
- [ ] У продукта нет действующей ДС: нет `workspace/product/ds/CONTRACT.md`.
- [ ] Файлов в `ds/` ещё нет, либо пользователь явно разрешил их перезаписать.
- [ ] Контекст продукта из `context/` прочитан.

## Фаза 1. Бриф

- [ ] Пять вопросов заданы одним блоком.
- [ ] Ответы из `context/` подставлены и подтверждены, а не спрошены заново.
- [ ] Длинные ответы сведены к ключевому и подтверждены («зафиксировал X, верно?»).
- [ ] `ds/brand-brief.md` сохранён.

## Фаза 2. Foundation

- [ ] Акцент: 5 оттенков (100, 300, 500, 700, 900), выбор тона обоснован брифом.
- [ ] 9 нейтралов: 00, 50, 100, 200, 300, 500, 700, 900, 950.
- [ ] 4 функциональных: success, warning, error, info.
- [ ] Шрифт поддерживает кириллицу при локали `ru` / `ru+en`; для `ru+en` указан резервный шрифт.
- [ ] Шкала размеров xs 12 … 4xl 48, веса 400/500/600/700.
- [ ] Межстрочный +3–5% при кириллице, межбуквенный на крупных заголовках от −0.5 до −1%.
- [ ] Радиусы 0/4/8/16, отступы 4/8/12/16/24/32/48/64, тени sm/md/lg без бренд-цвета.
- [ ] Каждый смысловой токен ссылается на существующий примитив.
- [ ] Имена в kebab-case, без дублей.
- [ ] **Файл показан пользователю, апрув получен.**

## Фаза 3. Figma

### Подготовка
- [ ] Получена ссылка на Figma Design-файл продукта (тот же, где wireframes), `fileKey` извлечён.
- [ ] Вызван `create_session`, загружен скилл `figma-use`.

### Variables (3.1)
- [ ] Коллекция `Primitive` создана, количество переменных совпадает с `foundation.md`.
- [ ] Коллекция `Semantic` создана, **все** значения имеют тип `VARIABLE_ALIAS`.
- [ ] Имена точно совпадают с `foundation.md`.
- [ ] Проверка сделана отдельным read-only вызовом.

### Foundation и компоненты (3.2–3.3)
- [ ] `SectionNode` «Foundation» стоит рядом с «Wireframes — low-fi», фон привязан к `surface-subtle`.
- [ ] Блоки Palette, Typography, Radii, Spacing стоят сверху горизонтально.
- [ ] `Components` ниже, Auto Layout, `layoutWrap = WRAP`, `itemSpacing = 32`.
- [ ] `Button`, `Input`, `Badge` имеют тип `COMPONENT_SET` с вариантами `State=…` / `Variant=…`.
- [ ] `Card`, `Modal`, `Navbar`, `IconButton` имеют тип `COMPONENT`.
- [ ] `getLocalTextStylesAsync()` возвращает 10 стилей `DS/…`.
- [ ] У всех text-узлов в Foundation непустой `textStyleId`.
- [ ] Цвет текста задан через `fills` с биндингом к Semantic.
- [ ] Нет SOLID-заливок или обводок без привязки к Variable.
- [ ] Радиусы привязаны по четырём углам, отступы привязаны к `space-*`.
- [ ] Auto Layout на всех секциях и компонентах.
- [ ] Ни один мутирующий вызов не заканчивается `throw`.
- [ ] Скриншот секции показан пользователю.
- [ ] Пользователь подтвердил: fill у Button помечен как Variable, смена `accent-500` перекрашивает компоненты.
- [ ] `ds/components.md` записан с фактическими Node ID.

## Фаза 4. Контракт

- [ ] `ds/CONTRACT.md` создан, ссылка на Figma-файл и дата заполнены.
- [ ] Корневые `CLAUDE.md` и `AGENTS.md` не изменены.
- [ ] Финальный отчёт выдан по шаблону.

## Частые ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| Лог «applied=N», а в файле пусто | `throw` в конце мутирующего вызова откатил транзакцию | Убрать `throw`, отчёт делать отдельным вызовом |
| `findOne` возвращает `FRAME` | Компонент собран через `createFrame` | Пересоздать через `createComponentFromNode` |
| Стиль не находится по имени | Figma нормализовала пробелы вокруг `/` | Сравнивать `name.replace(/\s*\/\s*/g, "/")` |
| Смена акцента не перекрашивает часть узлов | Остался прибитый SOLID | Найти fill без `boundVariables` и привязать к Semantic |
| `setValueForMode` в Semantic с RGB | Прибитое значение в смысловом слое | Заменить на `VARIABLE_ALIAS` к примитиву |
