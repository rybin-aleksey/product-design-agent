# Шаблоны выходных данных

`ds/` означает `workspace/product/ds/`.

| Файл | Фаза | Назначение |
|---|---|---|
| `ds/source.md` | 1 | Что сканировали и откуда |
| `ds/foundation.md` | 2 | Индекс токенов |
| `ds/components.md` | 3 | Каталог компонентов с Node ID |
| `ds/CONTRACT.md` | 5 | Правила работы с ДС |
| `ds/patterns.md` | — | Опционально, заводится после сканирования |

Корневые `CLAUDE.md` и `AGENTS.md` не меняются: агент находит контракт по правилу в `AGENTS.md`.

## ds/CONTRACT.md

```markdown
# DS Contract — правила работы с дизайн-системой продукта <название продукта>

**Источник ДС:** ds_scan (<своя / корпоративная / дублированная Community-библиотека>)
**Figma-файл:** <ссылка на страницу Components>
**Дата сканирования:** <ISO-дата>
**Артефакты:** workspace/product/ds/

## Главное правило

При любом задании, которое касается интерфейса продукта (новый экран, форма, карточка, доработка существующего), агент работает строго через эту ДС. Сборка идёт композицией существующих компонентов из `components.md` и существующих Variables из `foundation.md`. Прибитые цвета, размеры, радиусы и шрифты в обход Variables запрещены.

## Что значит «через ДС»

1. **Компоненты — только из каталога.** Агент читает `components.md`, выбирает компоненты по назначению и матрице вариантов и вставляет инстансы через `use_figma` по Node ID. Похожие с нуля не рисует.
2. **Цвета — только через Semantic Variables** из `foundation.md`. Никаких прибитых hex.
3. **Типографика, радиусы, отступы — через Variables** из коллекций исходной ДС.
4. **Auto Layout везде.** Любая секция экрана собирается в Auto Layout.

## Что делать, если нужного нет

<оставить ОДИН вариант по источнику из source.md>

### Вариант для источника «своя» или «дублированная Community»

**Нет компонента под задачу:**
1. Добавить компонент в Figma-файл ДС (страница Components) как набор с матрицей вариантов и описанием.
2. Перезапустить ds_scan или дописать строку в `components.md`: имя, назначение, варианты, Node ID.
3. Только после этого использовать на экране.

**Нет смыслового токена:**
1. Добавить Variable в коллекцию Semantic исходной ДС с привязкой к примитиву.
2. Дописать в `foundation.md`.
3. Только после этого использовать на экране.

### Вариант для источника «корпоративная»

**Нет компонента под задачу:**
1. ДС править нельзя — её ведёт другая команда.
2. Сначала собрать решение композицией существующих компонентов.
3. Если не получается — записать в `patterns.md` с пометкой «локальный паттерн, не часть корпоративной ДС». На экране собирать композицией существующих, свой компонент в файле ДС не создавать.
4. Параллельно завести запрос в команду ДС. Когда компонент появится, следующий ds_scan его подхватит, локальный паттерн убирается.

**Нет смыслового токена:**
1. Использовать ближайший существующий из Semantic корпоративной ДС.
2. Если совсем не подходит — отметить в `patterns.md` как ограничение и завести запрос в команду ДС.

## Паттерны композиций

`patterns.md` — опциональный файл рядом с этим, заводится по мере появления типовых раскладок (форма заказа, карточка товара, шапка таблицы, пустое состояние, уведомление). Каждый паттерн: имя, из каких компонентов и токенов собирается, Node ID примера в Figma.

## Синхронизация Figma ↔ md

`foundation.md` и `components.md` — индекс, по которому работает агент. Расхождение индекса с Figma ломает следующие сборки.

- ДС в Figma поменялась (своя / дублированная) → перезапустить ds_scan, перезаписать `foundation.md` и `components.md`.
- Корпоративная ДС обновилась → периодически (например, раз в спринт) перезапускать ds_scan, сравнивать с предыдущей версией, помечать устаревшие записи.
- Индекс не правится руками без сверки с Figma. Если правка ручная — пометить дату и причину, иначе следующий ds_scan её затрёт.

## Что запрещено

- Прибитые цвета, размеры, радиусы и отступы там, где есть подходящий Variable.
- Создание нового компонента «на лету» в составе экрана, если его можно собрать из существующих или вынести в ДС (для своей / дублированной).
- Правки в файле корпоративной ДС без согласования с командой ДС.
- Вторая параллельная ДС для этого же продукта.

## Когда правила можно нарушить

Только по явной команде пользователя «здесь без ДС, ad-hoc» (например, одноразовый рендер для презентации). Тогда делается отдельный фрейм вне секций продукта с пометкой «ad-hoc, не часть продукта».
```
