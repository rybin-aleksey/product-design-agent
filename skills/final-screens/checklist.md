# Чек-лист: сборка финальных экранов

Проходи по гейтам последовательно. Непройденный пункт значит, что следующая фаза не начинается.
`ds/` — `workspace/product/ds/`, `task/` — `workspace/product/tasks/<TASK-ID>/`.

## Перед стартом

- [ ] Папка задачи определена.
- [ ] `ds/CONTRACT.md`, `ds/foundation.md`, `ds/components.md` прочитаны целиком; контекст продукта прочитан.
- [ ] Режим определён: single или bulk. Bulk: список несобранных wireframes показан, решения по каждому получены.

## Фаза 0. Ресурсы

- [ ] Библиотека иконок известна (из `ds/icons.md` / `CONTRACT.md` или ответа пользователя); запись в `CONTRACT.md` — только с согласия.
- [ ] Тени в Foundation и EffectStyles проверены; отсутствие сообщено пользователю.

## Фаза 1. Read

- [ ] Wireframe найден и прочитан read-only (или пользователь явно разрешил собирать без него).
- [ ] Каталог прочитан целиком.
- [ ] Для каждой секции есть кандидат из ДС или решение пользователя (вынос / ближайший / плейсхолдер).
- [ ] Анализ достаточности: решение по каждому из шести пунктов.
- [ ] Повторяющиеся блоки найдены; по каждому решение «выносим / локально / отложить».

## Фаза 2. Composition map

- [ ] `task/artifacts/design/screens/<name>.md` создан по шаблону.
- [ ] Секции с Auto Layout, sizing, фоном, тенью; компоненты с Node ID и вариантами; иконки по имени; мета структурирована; edge cases; демо-контент помечен.
- [ ] **Апрув получен.** До этого — ни одного мутирующего MCP-вызова.

## Фаза 2.5. Вынос в UI-кит (если был)

- [ ] Брифы в `task/analysis/final-screens-extract-<name>.md`, апрув получен.
- [ ] Новые Semantic — только alias, апрув получен.
- [ ] Токены созданы в Figma, компоненты — пакетами ≤ 3, проверка после каждого пакета.
- [ ] `ds/components.md`, `ds/foundation.md`, composition map обновлены.
- [ ] Корпоративная ДС: вместо выноса — запись в `ds/patterns.md`.

## Фаза 3. Pre-canvas check

- [ ] Все десять пунктов закрыты.

## Фаза 4. Canvas

- [ ] Секция «Screens» создана рядом с «Wireframes» или переиспользована.
- [ ] Один экран — один мутирующий вызов (или скелет + секции), без `throw` в конце.
- [ ] Проверка: instance вместо frame, привязки цветов, Auto Layout и sizing, TextStyles, скрытые edge cases, число плейсхолдеров.
- [ ] Скриншот показан, Final Screen Node ID записан в карту.

## Фаза 5–6. Каталог и отчёт

- [ ] `used in` дописан у всех задействованных компонентов.
- [ ] `task/artifacts/design/screens/_index.md` обновлён.
- [ ] Отчёт выдан по шаблону; плейсхолдеры и демо-контент перечислены.
- [ ] Корневые `CLAUDE.md` и `AGENTS.md` не изменены.

## Частые ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| Секции не тянутся, экран «каменный» | `FIXED × FIXED` или `resize()` на секциях | Sizing по таблице через `layoutSizing*` после `appendChild` |
| `layoutSizingHorizontal` падает с ошибкой | Свойство задано до `appendChild` или у родителя нет Auto Layout | Сначала `appendChild` в Auto Layout-родителя |
| На месте компонента `FRAME` | Мастер склонирован или инстанс детачнут | Пересобрать блок через `createInstance()` |
| Не тот вариант у инстанса | Инстанс от первого попавшегося варианта | `defaultVariant.createInstance()` + `setProperties` |
| Серые квадраты вместо иконок | Пропущена фаза 0.1 | Выбрать библиотеку, отрендерить SVG |
| Карточки плоские, сливаются с фоном | Тени не применены | EffectStyles по маппингу |
| Экран пустой ниже первого экрана | Wireframe перенесён 1:1 | Вернуться к фазе 1.4, предложить секции |
| Лог «applied», в файле пусто | `throw` в конце мутирующего вызова | Проверка — отдельным read-only вызовом |
