# Передача проекта на GitHub (handoff)

## Назначение

Отдать результат разработке через GitHub: залить выбранную часть **одним коммитом и одним `git push`** и дать ссылку.
шаги для пользователя → что заливаем → подготовка и пуш → README и запись в `project.md` → проверка и ссылка.
Командную строку ведёт агент; пользователь проходит только браузерные шаги.

## Когда использовать

- Запускается из ветки «Передача разработке» в [workflows/design-task](../../workflows/design-task/README.md) **только по явной команде пользователя** (`handoff`, «передай проект разработке», «залей на GitHub»). Сама команда — прямое указание на commit и push по `AGENTS.md`; на другие репозитории и ветки оно не распространяется.
- Обычно после [storybook-catalog](../storybook-catalog/SKILL.md): есть законченный артефакт (база + каталог).
- Повторный запуск: репозиторий уже записан в `workspace/product/project.md` — вносим изменения (фаза 5).

## Роль

Инженер, который сопровождает дизайнера при передаче в разработку: ведёт git за него, объясняет браузерные шаги простыми словами, следит, чтобы в репозиторий не попали секреты и мусор.

## Предусловия

- Аккаунт на GitHub.
- `git` в системе (`git --version`).
- Авторизация для пуша — одно из (по приоритету):
  1. уже настроенные учётные данные: Git Credential Manager (`git config --get credential.helper` = `manager`) — вход через браузер при первом пуше, токен не нужен; или `gh auth status` — залогинен;
  2. токен (classic) с минимальными правами, который создаёт пользователь по шагам фазы 0.
- Коннектор GitHub на claude.ai для пуша **не нужен**: заливка идёт через `git`.

## Фазы

| Фаза | Что делаем | Результат | Гейт |
|---|---|---|---|
| 0. Шаги и проверки | `git --version`, способ авторизации, шаги «создать пустой репозиторий» (+ токен при необходимости) | Ссылка на пустой репозиторий | Пользователь прислал ссылку |
| 1. Что заливаем | Весь проект / React-база / прототип; `.gitignore`; проверка на секреты | Список и объём файлов | **Подтверждение состава** |
| 2. Пуш | Один коммит, один `git push` в `main` | Репозиторий заполнен | Пуш прошёл |
| 3. README и запись | README для разработчика, раздел в `project.md` | Документация | — |
| 4. Проверка | Ветка, файлы, README, нет служебного | HTTPS-ссылка | Self-check пройден |
| 5. Повторный запуск | Обновление того же репозитория: `main` или отдельная ветка | Обновление | Ветка подтверждена |

Подробности и команды — в [methodology.md](methodology.md).
Self-check — в [checklist.md](checklist.md).
Тексты шагов для пользователя и финальный отчёт — в [output-template.md](output-template.md).

## Жёсткие правила

1. **Один коммит, один пуш** всего выбранного. Пофайловая заливка через API запрещена.
2. **Не трогать `origin` и `template` продукта.** Репозиторий для разработки — отдельный remote `handoff` (весь проект) или отдельная рабочая копия в scratchpad (часть проекта).
3. **Секреты не уходят.** `.env*` (кроме `.env.example`), ключи, токены, `credentials*` — в `.gitignore` и проверены поиском до коммита.
4. **Служебное не уходит:** `node_modules/`, `dist/`, `build/`, `storybook-static/`, `.tmp/`, `.DS_Store`, логи.
5. **Токен транзиентный.** Используется только в одной команде пуша; не пишется в файлы, `.git/config`, коммиты, `project.md`, не повторяется в ответах. После передачи — рекомендация отозвать.
6. **Пустой репозиторий.** Если в нём уже есть коммиты (README / license) — `pull --rebase` перед пушем, без `--force`.
7. **Перед пушем — подтверждение** состава и адреса репозитория: публикация необратима, даже если потом удалить.
8. **Файлы шаблона агента не меняются.** README для разработчика кладётся в заливаемую часть, а не в корневой `README.md` шаблона.
9. **Повторный запуск — тот же репозиторий.** Незаконченная итерация — в отдельную ветку, `main` не трогаем.

## Где сохранять

```text
product-design-agent/
└── workspace/product/
    ├── project.md               # раздел «Репозиторий разработки»: ссылка, ветка, что залито, дата
    └── code/README.md           # README для разработчика (если заливается React-база)
```

Рабочая копия для заливки части проекта — в scratchpad сессии, не в репозитории продукта.
Корневые `CLAUDE.md`, `AGENTS.md`, `README.md` не меняются.
