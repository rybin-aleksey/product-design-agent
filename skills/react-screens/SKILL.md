# Сборка экрана из базы (screens)

## Назначение

Собрать экран продукта в React **из компонентной базы** по его дизайну в Figma, подключить к проекту и вывести плиткой на навигационную страницу-индекс.
контекст и каркас → ссылка на фрейм → чтение дизайна → декомпозиция → сборка страницы → реестр и индекс → запуск и проверка.
Результат — статичный, но настоящий экран: как выглядит и как держится по ширине и объёму контента.

## Граница: что НЕ делаем

Только раскладка и статичный вид. Скилл **не**:
- пишет логику и обработчики;
- строит слой данных и состояние, не генерирует мок-датасеты, не делает контент динамическим;
- делает рабочие формы, навигацию-как-действие и переходы по клику внутри экрана.

Это следующий шаг — оживление экранов, скилл [react-wire](../react-wire/SKILL.md). Даже если «логично сразу» — на этом шаге не делаем: иначе следующему шагу не остаётся работы, а задачи смешиваются. Единственная навигация здесь — переход с плитки индекса на экран и обратно.

## Когда использовать

- Запускается из ветки «Сборка экранов в коде» в [workflows/design-task](../../workflows/design-task/README.md) **только по явной команде пользователя со ссылкой на фрейм экрана**. Это задача с кодом — прямой запрос обязателен по `AGENTS.md`.
- Есть React-база в `workspace/product/code/` (`src/components/`, `src/tokens/`), проект поднимается. Каталог [storybook-catalog](../storybook-catalog/SKILL.md) не обязателен, но удобен для сверки.
- Дизайн экрана есть в Figma отдельным фреймом — обычно `Screen/<Name>` из [final-screens](../final-screens/SKILL.md).
- Переиспользуемый: новый экран — добавляется; уже собранный — обновляется (фаза 7). Реестр копит все экраны.

**Не использовать**, если React-базы нет — сначала её нужно собрать (react_base; скилла в шаблоне пока нет).

## Роль

Фронтенд-разработчик, который собирает страницы из готовой дизайн-системы: узнаёт компоненты в макете, переносит Auto Layout в отзывчивую вёрстку, держит стили на токенах и не выходит за границу задачи. Дизайнер направляет и смотрит результат, код правит агент.

## Входные данные

- `ds/CONTRACT.md`, `ds/components.md`; `code/src/components/index.ts`.
- Ссылка на фрейм экрана в Figma (не на корень файла).
- Composition map экрана, если есть: `workspace/product/tasks/*/artifacts/design/screens/<name>.md` (по Final Screen Node ID) — подсказка по компонентам, вариантам и локальным блокам.
- Контекст продукта — для заголовка индекса.

## Фазы

| Фаза | Что делаем | Результат | Гейт |
|---|---|---|---|
| 0. Контекст | ДС, база, каркас экранов (роутер, реестр, индекс) | Среда для экранов | Каркас есть или заведён |
| 1. Вход | Ссылка на фрейм, имя экрана | `fileKey`, `nodeId`, имя | Ссылка именно на фрейм |
| 2. Дизайн | `get_metadata` → `get_design_context` по секциям → `get_screenshot` | Структура, раскладка, референс | — |
| 3. Декомпозиция | Блок → компонент базы / локальный блок | Карта блоков | Спорные блоки решены пользователем |
| 4. Сборка | Отзывчивая раскладка, токены, статичный контент | `src/screens/<name>/` | Без логики и данных |
| 5. Подключение | Реестр, индекс «/», заметка экрана | Экран открывается с индекса | Индекс строится из реестра |
| 6. Проверка | `npm run dev`, сверка с Figma, ширина и длинный контент | Роут и результат | Self-check пройден |
| 7. Повтор | Новый — добавить; тот же — обновить | — | Без дублей роутов |

Подробности, маппинг раскладки и шаблоны кода — в [methodology.md](methodology.md).
Self-check — в [checklist.md](checklist.md).
Шаблоны заметки, реестра и отчёта — в [output-template.md](output-template.md).

## Жёсткие правила

1. **Экран — композиция из базы.** Компоненты базы не перерисовываются и не правятся ради экрана.
2. **Нет точного компонента — локальный блок** в `src/screens/<name>/parts/` из базы и токенов, а не подмена чужим компонентом.
3. **Только семантические токены** (`CONTRACT`): ни одного прибитого hex / px там, где есть токен.
4. **Раскладка отзывчивая:** Auto Layout и констрейнты → flex / grid; прибитые координаты запрещены.
5. **Статика из макета:** те же тексты и значения, что в дизайне; без логики, обработчиков, состояния, данных.
6. **Figma — read-only.**
7. **Реестр — единая точка:** каждый экран регистрируется; индекс на «/» строится из реестра, плитки не хардкодятся.
8. **Новые зависимости** (например, роутер) — только с согласия пользователя.
9. **Ничего не коммитим** без прямого указания.

## Где сохранять

```text
workspace/product/code/
└── src/
    ├── screens/
    │   ├── registry.ts               # реестр экранов: id, name, description, route, component
    │   ├── ScreensIndex.tsx          # навигационная страница «/», строится из реестра
    │   └── <name>/
    │       ├── <Name>.tsx            # страница экрана
    │       ├── <Name>.module.css     # стили экрана на токенах (или принятый в базе способ)
    │       ├── parts/                # локальные доменные блоки
    │       └── <name>.md             # заметка экрана
    └── <точка входа и роутер>        # как принято в базе
```

Если структура базы другая (другой способ стилей, роутер уже есть) — следуй ей. Корневые `CLAUDE.md` и `AGENTS.md` не меняются.
