# Методология: каталог в Storybook

`code/` — `workspace/product/code/` (корень React-базы), `ds/` — `workspace/product/ds/`.
Все команды выполняются в `code/`. Гейты — в [checklist.md](checklist.md).

---

## Фаза 0. Контекст

1. Прочитай `ds/components.md` (состав, матрицы вариантов и состояний) и `ds/foundation.md` (все токены).
2. Прочитай `code/src/components/index.ts` и структуру `code/src/tokens/`.
3. Построй таблицу: компонент → есть в `components.md` / есть в базе / есть story.
   - Есть в базе — попадает в каталог.
   - Есть в `components.md`, нет в базе — в отчёт «не попало: нет в базе» (каталог его не рисует).
   - Варианты в базе ≠ матрице в `components.md` — показать пользователю до написания stories.
4. Проверь окружение: `node -v` (18+), `npm -v`, проект ставится и собирается (`npm install` при отсутствии `node_modules`).

---

## Фаза 1. Установка

1. Есть `code/.storybook/` — Storybook стоит, init **не запускать**, переход к фазе 2.
2. Иначе `npx storybook@latest init --yes` — без `--yes` init задаёт вопросы и зависает в неинтерактивном запуске. Init сам определит Vite + React, создаст `.storybook/`, скрипты `storybook` / `build-storybook` и примеры.
3. Удали примеры init (`src/stories/`) — в каталоге только своё.
4. В `.storybook/preview.ts(x)` подключи глобальные стили: `import '../src/tokens/<файлы>.css'` и шрифт так же, как в приложении (тот же импорт, что в entry базы). Без этого компоненты в каталоге без темы и шрифта.
5. Autodocs и docs-аддон в конфиге не удалять: на них держатся страницы с таблицей пропсов, контролами и Copy code.
6. Порядок разделов в сайдбаре — через `parameters.options.storySort` в preview: `['Foundation', 'Components', 'Sandboxes']`.

## Фаза 2. Foundation

Раздел `Foundation` (stories или MDX) — все переменные наглядно. Значения читаются из `src/tokens/` (TS-объекты или CSS custom properties через `getComputedStyle(document.documentElement)`), не хардкодятся.

- `Foundation/Primitive` — палитра (акцент, нейтралы, функциональные, альфа), размеры шрифта, веса, line-height, letter-spacing, радиусы, отступы, тени: свотч / образец + имя + значение.
- `Foundation/Semantic` — все смысловые токены с подписью, на какой примитив ссылаются (`surface-action-primary → accent-500`).
- `Foundation/Typography` — каждый текстовый стиль строкой-примером на кириллице и латинице (если локаль `ru+en`).

Сверь число токенов с `ds/foundation.md`; недостающие в `src/tokens/` — в отчёт, не добавлять молча.

## Фаза 3. Stories на все компоненты

Для **каждого** компонента базы — `src/components/<Name>/<Name>.stories.tsx` по каноническому шаблону из [output-template.md](output-template.md). Формат одинаков для всех.

1. `tags: ['autodocs']` в `meta` — у каждого компонента. Без тега нет страницы с таблицей пропсов, контролами и Show code / Copy code.
2. `argTypes` на каждый проп: перечисление → `inline-radio` (≤ 4 значений) или `select` + `options`; boolean → `boolean`; строка / ReactNode-текст → `text`; объект / массив → `object`; колбэки → `action` (или `fn()` из `storybook/test`).
3. `args` — осмысленные значения из контекста продукта, на языке локали; не lorem.
4. Именованные stories — на каждое значимое значение матрицы из `components.md` (Primary / Secondary / Ghost; Default / Error / Disabled).
5. `AllVariants` — `render` со всей матрицей вариантов × состояний на одном холсте, подписи осей, реальные инстансы базы. Для матрицы больше ~24 ячеек — сетка по двум осям, третья ось — отдельными `AllVariants<Ось>`.
6. JSDoc `/** … */` над `meta` и над stories — назначение из `components.md`.
7. Импорт — реальный компонент из `./`; иконки — библиотека из `ds/CONTRACT.md` / `ds/icons.md` (например, `lucide-react`); не добавлять новых зависимостей без необходимости.
8. Пакет импорта — тот, который поставил init (`@storybook/react-vite` для Vite). Сверься с `.storybook/main.ts`.

Если у компонента состояние задаётся только CSS-псевдоклассом (hover без пропа) — в `AllVariants` показывай его через проп, если он есть, иначе через аддон `storybook-addon-pseudo-states` только по согласию пользователя (это новая зависимость).

## Фаза 4. Живые переходы

1. Проверь у интерактивных компонентов (Button, IconButton, Input, Tabs, Select, Dropdown, Card interactive) `transition` на `background-color`, `border-color`, `box-shadow`, `color` для `:hover`, `:active`, `:focus-visible`.
2. Нет — добавь в стили базы: 150–200 ms ease. Длительность и easing — через токены, если в базе есть motion-токены; если нет — предложи завести (`--motion-duration-fast`, `--motion-ease-standard`) и согласуй, это правка Foundation.
3. Уважай `prefers-reduced-motion`: переходы отключаются в `@media (prefers-reduced-motion: reduce)`.
4. В stories наведение и нажатие должны отрабатывать нативно: состояние-проп (`state="hover"`) — для статичной матрицы, а дефолтная story — без фиксированного состояния.

Правки базы перечисли в отчёте.

## Фаза 5. Песочницы по блокам

На каждый логический блок — story `title: 'Sandboxes/<Блок>'`, только из инстансов базы, со связанным состоянием (`useState` в `render`):

| Песочница | Состав (если компоненты есть в базе) |
|---|---|
| Modal | Modal + заголовок + Input + Badge + Button secondary / primary; открыть / закрыть |
| Form | Input / Select / Dropdown + submit / cancel; ошибки полей при сабмите |
| Navigation | Navbar + Tabs + Breadcrumb + Pagination, переключение активного |
| Data & Feedback | Table + Toast + Tooltip; действие в таблице показывает Toast |

Блок, для которого в базе нет компонентов, пропускается и упоминается в отчёте. Состав песочниц адаптируй под продукт (по контексту и собранным экранам).

## Фаза 6. Сложные компоненты — по желанию

Для Table, Select, Dropdown, Toast, Modal (если есть в базе) спроси одним блоком:

> По <Name> можно добавить отдельные кейсы: длинный контент, крайние состояния (пусто, много элементов, ошибка), микро-анимации появления. Сделать? Для каких?

Да — stories `EdgeCases/<Кейс>` в файле компонента. Нет — пропуск, базовый набор полный.

## Фаза 7. Запуск и проверка

1. `npm run storybook -- --ci` — **в фоне** (процесс не завершается); дождись адреса (обычно `http://localhost:6006`). `--ci` не открывает браузер и не ждёт ввода.
2. Сборочная проверка: `npm run build-storybook` (без ошибок и предупреждений о сломанных stories) и проверка типов, если в проекте есть `tsc`.
3. Self-check из [checklist.md](checklist.md); при возможности открой каталог во встроенном браузере и пройди по разделам.
4. Покажи пользователю адрес и состав. Дальше он сверяет каталог с Figma и называет расхождения словами — правки в базу или stories вносит агент.

---

## Фаза 8. Повторный запуск = обновление

- Init не трогаем.
- Сверка фазы 0: новые компоненты базы → новые stories; изменившиеся матрицы → обновлённые `argTypes`, именованные stories и `AllVariants`; новый блок → песочница.
- Существующие stories не переписываем целиком и не дублируем; ручные правки пользователя в stories сохраняем.
- В отчёте — что добавлено / обновлено.
