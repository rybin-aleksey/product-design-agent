# Дашборд юзер-тестов (dashboard)

## Назначение

Подключить готовый дашборд юзер-тестов к живой версии прототипа:
контекст и план теста → сбор на сервере → публичный адрес сбора → трекер в прототипе → `config.js` и гипотезы → передеплой и проверка → раунды и цикл с агентом.
Живая версия шлёт поведение → сбор копит → дашборд показывает метрики, вердикты по гипотезам и даёт задание агенту.

## Почему сбор на своём сервере

Сессии, клики и тайминги копятся во времени — их принимает и хранит маленький сервер из бандла (Node, без зависимостей, события в файл). На Vercel / Netlify ему негде жить: там статика и короткие функции без постоянного диска. Поэтому прототип может быть где угодно, а **данные — на своём VPS**. Управляемую БД не поднимаем: для юзер-тестов прототипа файлового хранилища достаточно.

## Два пути (по тому, где прототип)

| | Путь 1: прототип на своём сервере | Путь 2: прототип на Vercel / сервисе |
|---|---|---|
| Протокол прототипа | `http://<IP>` | `https://…` |
| Адрес сбора | `http://<IP>:<порт>` | `https://<постоянный-адрес>.ngrok-free.app` (туннель) |
| Почему | Один протокол | HTTPS-страница не может слать на http — mixed content |
| Порт сбора наружу | Открыть | Не нужно — туннель изнутри сервера |

Путь берётся из раздела «Публикация» в `workspace/product/project.md`; неясно — спросить.

## Когда использовать

- Запускается из ветки «Юзер-тесты на прототипе» в [workflows/design-task](../../workflows/design-task/README.md) **только по явной команде пользователя** (`dashboard`, «подключи дашборд юзер-тестов»): это изменения на сервере, в прототипе и публикация.
- Прототип опубликован ([deploy](../deploy/SKILL.md)), живая ссылка в `project.md`.
- Бандл распакован в `workspace/product/dashboard/` (`tracker/`, `server/`, `app/`, `README.md`). Нет — попросить положить.
- Повторный запуск: добавились экраны / поведение / сценарии / гипотезы — обновляем.

## Роль

UX-исследователь с инженерной практикой: превращает сценарии и гипотезы продукта в измеримый план теста, поднимает сбор и трекинг, не ломая ничего на сервере, и следит, чтобы метрики собирались честно и без персональных данных.

## Входные данные

- `workspace/product/dashboard/README.md` и код бандла — источник правды об API (`/health`, `/collect`, `/hypotheses`), переменных (`PORT`, `DATA_DIR`, `DASH_KEY`) и форматах (`config.example.js`, `hypotheses.example.json`).
- `workspace/product/project.md` — живая ссылка, путь деплоя, сервер.
- Сценарии: `code/src/screens/registry.ts`, роутер, разделы «Поведение» в заметках экранов (react-wire), `task.md`, PRD / спецификации задачи.
- Гипотезы: `task.md`, PRD, `artifacts/research/insights/`, `analysis/` задачи.
- Доступ к VPS (как в [deploy](../deploy/methodology.md), путь B1: SSH-ключ предпочтительно); для пути 2 — ngrok authtoken и постоянный адрес.

## Фазы

| Фаза | Что делаем | Результат | Гейт |
|---|---|---|---|
| 0. Контекст и план | README бандла, путь, порт; сценарии и гипотезы из проекта | `ut-plan.md`, `hypotheses.json` | **Апрув сценариев и порогов** |
| 1. Сбор | `server/` на VPS, systemd-служба, `/health` | Работающий сборщик | `curl localhost:<порт>/health` |
| 2. Адрес сбора | Путь 1: порт наружу; путь 2: ngrok-служба с постоянным адресом | Публичный адрес сбора | `/health` снаружи |
| 3. Трекер | `public/track.js`, `<script data-endpoint>`, `data-track` | Трекер в прототипе | Не `localhost` |
| 4. Config | `app/config.js`, где открыть дашборд | Дашборд «подключён» | `endpoint`, `prototypeUrl` верны |
| 5. Гипотезы | `POST /hypotheses` или `data/hypotheses.json` | Вердикты в дашборде | — |
| 6. Проверка | Передеплой, свой прогон по ссылке U-теста, раунд | Сессии в дашборде | Self-check пройден |
| 7. Цикл | Находки → задание агенту → правки → передеплой → ретест | Было → стало | — |
| 8. Повтор | Обновить трекер, сценарии, адрес | — | — |

Подробности и команды — в [methodology.md](methodology.md).
Self-check — в [checklist.md](checklist.md).
Шаблоны плана, конфигов и отчёта — в [output-template.md](output-template.md).

## Жёсткие правила

1. **Сценарии и гипотезы — из проекта.** Агент собирает их из материалов, пороги предлагает; финальные пороги и формулировки утверждает пользователь. Гипотез в материалах нет — не выдумывать, панель остаётся пустой или пользователь формулирует сам.
2. **Протоколы совпадают:** прототип на https → сбор только через https-туннель с постоянным адресом. `data-endpoint` никогда не `localhost`.
3. **Сбор и туннель — службами** (systemd / pm2), а не процессом в терминале.
4. **Сервер — аккуратно, как в deploy:** разведка read-only, план и подтверждение, свободный порт, VPN не задевать, неактивный `ufw` не включать.
5. **Доступы транзиентные:** пароль и токены — не в файлы проекта, `.git`, `project.md`, ответы. ngrok authtoken хранится только в конфиге ngrok на сервере (иначе служба не поднимется) — об этом сказать пользователю.
6. **`config.js` с ключом не коммитится**; ключ `DASH_KEY` — не в `project.md`.
7. **Без персональных данных:** до встраивания прочитать `track.js` и убедиться, что он не собирает ввод в поля; респондентов предупреждают, что поведение записывается.
8. **Не долбить живой URL на Vercel** частыми `curl` — бот-защита закроет сайт всем. Статус деплоя — по коммит-статусу на GitHub или разовая проверка.
9. **`prototypeUrl` — реальный первый экран сценария**, а не дев-индекс «/».
10. **Код бандла не переписывать**; правки прототипа — только трекер, `data-track` и (при необходимости) конфиг деплоя.

## Где сохранять

```text
workspace/product/
├── project.md                          # раздел «Юзер-тесты»: адрес сбора, путь, где дашборд, сценарии (без ключей и токенов)
├── dashboard/                          # бандл (кладёт пользователь)
│   └── app/config.js                   # генерирует агент; в .gitignore бандла
├── code/
│   ├── public/track.js                 # копия dashboard/tracker/track.js
│   └── index.html                      # <script src="/track.js" data-endpoint="…/collect">
└── tasks/<TASK-ID>/artifacts/validate/
    ├── ut-plan.md                      # сценарии, гипотезы, источники, раунды
    └── hypotheses.json                 # то, что ушло на сервер
```

Корневые `CLAUDE.md` и `AGENTS.md` не меняются.
